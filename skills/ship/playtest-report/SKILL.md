当使用 `new` 调用时，生成此模板：

```markdown
# 游戏测试报告

## 会话信息
- **日期**: [日期]
- **构建**: [版本/提交]
- **时长**: [游戏时间]
- **测试者**: [姓名/ID]
- **平台**: [PC/主机/移动]
- **输入方式**: [键鼠 / 手柄 / 触摸]
- **会话类型**: [首次 / 回归 / 针对性测试]

## 测试重点
[正在测试的特定功能或流程]

## 第一印象（前5分钟）
- **理解目标？** [是/否/部分]
- **理解控制？** [是/否/部分]
- **情感反应**: [投入/困惑/无聊/沮丧/兴奋]
- **备注**: [观察]

## 游戏流程
### 什么效果好
- [观察 1]
- [观察 2]

### 痛点
- [问题 1 -- 严重性: 高/中/低]
- [问题 2 -- 严重性: 高/中/低]

### 困惑点
- [玩家困惑的地方及原因]

### 愉悦时刻
- [什么让玩家惊讶或高兴]

## 遇到的错误
| # | 描述 | 严重性 | 可重现 |
|---|-------------|----------|-------------|

## 功能特定反馈
### [功能 1]
- **理解目的？** [是/否]
- **觉得有趣？** [是/否]
- **建议**: [测试者建议]

## 定量数据（如果可用）
- **死亡**: [计数和位置]
- **每区域时间**: [细分]
- **使用的物品**: [什么和何时]
- **发现 vs 错过的功能**: [列表]

## 整体评估
- **会再玩吗？** [是/否/可能]
- **难度**: [太简单 / 正好 / 太难]
- **节奏**: [太慢 / 好 / 太快]
- **会话长度偏好**: [更短 / 好 / 更长]

## 本次会话的前3个优先级
1. [最重要的发现]
2. [第二优先级]
3. [第三优先级]
```

当使用 `analyze` 调用时，读取原始笔记，与现有
设计文档交叉引用，并用结构化发现填写上面的模板。
标记任何与设计意图冲突的游戏测试观察。
