argument-hint: "[version] [--style brief|detailed|full]"
user-invocable: true
allowed-tools: Read, Glob, Grep, Write, Bash
---

当此skill被调用时：

1. **解析参数**：
   - `version`: 要生成说明的发布版本（例如，`1.2.0`）
   - `--style`: 输出样式 — `brief`（项目符号）、`detailed`（带上下文）、
     `full`（带开发者评论）。默认: `detailed`。

2. **从多个来源收集变更数据**：
   - 如果存在，读取 `production/releases/[version]/changelog.md` 的内部变更日志
   - 在之前的发布标签和当前标签/HEAD之间运行 `git log`
   - 从 `production/sprints/` 读取冲刺回顾以获取上下文
   - 从 `design/balance/` 读取任何平衡变更文档
   - 如果可用，从QA读取错误修复记录

3. **将所有变更分类**为面向玩家的类别：
   - **新内容**: 新功能、地图、角色、物品、模式
   - **游戏玩法变更**: 平衡调整、机制变更、进度变更
   - **生活质量**: UI改进、便利功能、无障碍
   - **错误修复**: 按系统分组（战斗、UI、网络等）
   - **性能**: 玩家可能注意到的优化改进
   - **已知问题**: 对未解决问题的透明度

4. **将开发者语言翻译成玩家语言**：
   - "重构伤害计算管道" → "改进命中检测准确性"
   - "修复库存管理器中的空引用" → "修复打开库存时的崩溃"
   - "减少战斗循环中的GC分配" → "改进战斗性能"
   - 删除不影响玩家的纯粹内部变更
   - 保留平衡变更的具体数字（伤害: 50 → 45）

5. **使用适当的样式生成补丁说明**：

### 简要样式
```markdown
# 补丁 [版本] — [标题]

**新内容**
- [功能 1]
- [功能 2]

**变更**
- [平衡/机制变更，包含之前 → 之后的值]

**修复**
- [错误修复 1]
- [错误修复 2]

**已知问题**
- [问题 1]
```

### 详细样式
```markdown
# 补丁 [版本] — [标题]
*[日期]*

## 亮点
[1-2句话总结最令人兴奋的变更]

## 新内容
### [功能名称]
[2-3句话描述功能以及为什么玩家应该兴奋]

## 游戏玩法变更
### 平衡
| 变更 | 之前 | 之后 | 原因 |
| ---- | ---- | ---- | ---- |
| [物品/能力] | [旧值] | [新值] | [简要理由] |

### 机制
- **[变更]**: [变更内容和原因的解释]

## 生活质量
- [带上下文的改进]

## 错误修复
### 战斗
- 修复了[玩家遇到的问题描述]

### UI
- 修复了[描述]

### 网络
- 修复了[描述]

## 性能
- [玩家会注意到的改进]

## 已知问题
- [问题和可用的变通方法]
```

### 完整样式
包含详细样式的所有内容，加上：
```markdown
## 开发者评论
### [主题]
> [对重大变更的开发者见解——为什么做出此变更、考虑了什么、
> 团队学到了什么。以第一人称团队声音撰写。]
```

6. **审查输出**：
   - 没有内部行话（用玩家友好的语言替换技术术语）
   - 没有引用内部系统、工单或冲刺编号
   - 平衡变更包含之前/之后的值
   - 错误修复描述玩家体验，而不是技术原因
   - 语气与游戏的声音匹配（基于游戏风格调整正式程度）

7. **将补丁说明保存**到 `production/releases/[version]/patch-notes.md`，
   如果需要则创建目录。

8. **向用户输出**：完整的补丁说明、文件路径、按类别统计的
   变更数量，以及任何被排除的内部变更（供审查）。
