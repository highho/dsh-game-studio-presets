---
name: bug-report
description: "从描述创建结构化错误报告，或分析代码以识别潜在错误。确保每个错误报告都有完整的重现步骤、严重性评估和上下文。"
argument-hint: "[描述]
/bug-report analyze [文件路径]"
user-invocable: true
allowed-tools: Read, Glob, Grep, Write
---

当使用描述调用时：

1. **解析描述**获取关键信息。

2. **使用Grep/Glob搜索代码库**以添加上下文。

3. **生成错误报告**：

```markdown
# 错误报告

## 摘要
**标题**: [简洁、描述性的标题]
**ID**: BUG-[NNNN]
**严重性**: [S1-严重 / S2-主要 / S3-次要 / S4-微小]
**优先级**: [P1-立即 / P2-下个冲刺 / P3-待办 / P4-愿望清单]
**状态**: 打开
**报告日期**: [日期]
**报告人**: [姓名]

## 分类
- **类别**: [游戏玩法 / UI / 音频 / 视觉 / 性能 / 崩溃 / 网络]
- **系统**: [受影响的游戏系统]
- **频率**: [总是 / 经常 (>50%) / 有时 (10-50%) / 很少 (<10%)]
- **回归**: [是/否/未知 -- 这以前有效吗？]

## 环境
- **构建**: [版本或提交哈希]
- **平台**: [操作系统、硬件（如相关）]
- **场景/关卡**: [游戏中哪里]
- **游戏状态**: [相关状态 -- 库存、任务进度等]

## 重现步骤
**前置条件**: [开始前所需状态]

1. [确切步骤1]
2. [确切步骤2]
3. [确切步骤3]

**预期结果**: [应该发生什么]
**实际结果**: [实际发生什么]

## 技术上下文
- **可能受影响的文件**: [基于代码库搜索的文件列表]
- **相关系统**: [可能涉及的其他系统]
- **可能根本原因**: [如果可以从描述中识别]

## 证据
- **日志**: [相关日志输出（如有）]
- **视觉**: [视觉证据描述]

## 相关问题
- [相关错误或设计文档的链接]

## 备注
[任何额外的上下文或观察]
```

当使用`analyze`调用时：

1. **读取目标文件**。
2. **识别潜在错误**：空引用、差一错误、竞态条件、未处理的边缘情况、资源泄漏、不正确的状态转换。
3. **对于每个潜在错误**，生成带有可能触发场景和建议修复的错误报告。
