---
name: architecture-decision
description: "创建架构决策记录(ADR)，记录重要的技术决策、其背景、考虑的替代方案和后果。每个重大技术选择都应该有一个ADR。"
argument-hint: "[标题]"
user-invocable: true
allowed-tools: Read, Glob, Grep, Write
---

当此skill被调用时：

1. **确定下一个ADR编号**，扫描`docs/architecture/`中的现有ADR。

2. **收集背景**，阅读相关代码和现有ADR。

3. **引导用户完成决策**，如果标题本身不足以说明问题，则提出澄清问题。

4. **生成ADR**，遵循以下格式：

```markdown
# ADR-[NNNN]: [标题]

## 状态
[提议中 | 已接受 | 已弃用 | 被ADR-XXXX取代]

## 日期
[决策日期]

## 背景

### 问题陈述
[我们要解决什么问题？为什么现在需要做出这个决策？]

### 约束
- [技术约束]
- [时间线约束]
- [资源约束]
- [兼容性要求]

### 需求
- [必须支持X]
- [必须在Y预算内执行]
- [必须与Z集成]

## 决策

[做出的具体技术决策，描述足够详细以便他人实现。]

### 架构图
[此决策创建的ASCII图或系统架构描述]

### 关键接口
[此决策创建的API合约或接口定义]

## 考虑的替代方案

### 替代方案1: [名称]
- **描述**: [这将如何工作]
- **优点**: [优势]
- **缺点**: [劣势]
- **拒绝原因**: [为什么未选择此方案]

### 替代方案2: [名称]
- **描述**: [这将如何工作]
- **优点**: [优势]
- **缺点**: [劣势]
- **拒绝原因**: [为什么未选择此方案]

## 后果

### 积极影响
- [此决策的良好结果]

### 消极影响
- [接受的权衡和成本]

### 风险
- [可能出错的事情]
- [每种风险的缓解措施]

## 性能影响
- **CPU**: [预期影响]
- **内存**: [预期影响]
- **加载时间**: [预期影响]
- **网络**: [预期影响，如适用]

## 迁移计划
[如果此更改影响现有代码，我们如何从这里到达那里？]

## 验证标准
[我们如何知道此决策是正确的？什么指标或测试？]

## 相关决策
- [相关ADR的链接]
- [相关设计文档的链接]
```

5. **保存ADR**到`docs/architecture/adr-[NNNN]-[slug].md`。
