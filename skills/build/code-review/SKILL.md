当此skill被调用时：

1. **完整读取目标文件**。

2. **读取CLAUDE.md**获取项目编码标准。

3. **识别系统类别**（引擎、游戏玩法、AI、网络、UI、工具）
   并应用类别特定标准。

4. **评估编码标准**：
   - [ ] 公共方法和类有文档注释
   - [ ] 每个方法的圈复杂度低于10
   - [ ] 没有方法超过40行（不包括数据声明）
   - [ ] 依赖被注入（游戏状态没有静态单例）
   - [ ] 配置值从数据文件加载
   - [ ] 系统暴露接口（而非具体类依赖）

5. **检查架构合规性**：
   - [ ] 正确的依赖方向（引擎 <- 游戏玩法，而非反向）
   - [ ] 模块之间没有循环依赖
   - [ ] 正确的层分离（UI不拥有游戏状态）
   - [ ] 事件/信号用于跨系统通信
   - [ ] 与代码库中已建立的模式一致

6. **检查SOLID合规性**：
   - [ ] 单一职责：每个类只有一个改变的理由
   - [ ] 开闭原则：无需修改即可扩展
   - [ ] 里氏替换：子类型可替换基类型
   - [ ] 接口隔离：没有胖接口
   - [ ] 依赖倒置：依赖抽象，而非具体

7. **检查常见游戏开发问题**：
   - [ ] 帧率独立（delta时间使用）
   - [ ] 热路径中没有分配（更新循环）
   - [ ] 适当的空/空状态处理
   - [ ] 需要时的线程安全
   - [ ] 资源清理（无泄漏）

8. **以此格式输出审查**：

```markdown
## 代码审查: [文件/系统名称]

### 标准合规性: [X/6 通过]
[列出带有行引用的失败]

### 架构: [干净 / 小问题 / 发现违规]
[列出具体架构问题]

### SOLID: [合规 / 发现问题]
[列出具体违规]

### 游戏特定问题
[列出游戏开发特定问题]

### 积极观察
[做得好的地方 -- 始终包含此部分]

### 必需更改
[批准前必须修复的项目]

### 建议
[可选改进]

### 裁决: [批准 / 批准并建议 / 需要更改]
```
